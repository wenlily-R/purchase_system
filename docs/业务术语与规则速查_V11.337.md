# 正成能源采购系统 · 业务术语与规则速查（V11.337）

> 用途：新人培训、日常对齐、交接留档。系统内同一份内容在页头「📖 术语规则」按钮里（点节点可跳转到对应页面）。
> 维护规则：新业务先定叫法再开发；本表与四张流程图（📋物资采购 / ⚡应急采购 / 📦库房 / 🔧设备维修）、流程说明书三者同步更新。

## 一、入库只有四条线（不再有第五种叫法）
| 叫法 | 触发场景 | 硬性要求 |
|---|---|---|
| 常规入库 | 有采购订单的到货 | 必须关联采购订单 |
| 手工应急入库 | 货先到、单后到 | 上传送货单+现场照片、标记"临时手工入库"、事后补关联；**未补关联禁止付款** |
| 现场核验入库 | 大件直装现场 | 现场拍照后补单 |
| 应急采购临时入库 | 应急单验收通过 | 先进「临时待分配库」，再由库管分配到正式库房 |

## 二、临时待分配库是过渡库，不是实体库
- 性质：应急采购的货物落地中转库（虚拟库，含"待检区"子节点）；
- 动作：库管按用途分配到 生产库／生活库／工程材料库／气体库／再用库／废旧物资库；
- 纠错：分配错误可**撤回重分**，全程留痕；
- 记忆点：**实体库是"家"，临时待分配库是"中转站"**。

## 三、单据与状态
- **应急采购单 ≠ 应急入库单**：前者记"买什么、多少钱"（询价→定标→订单），后者记"实际收到多少"。两张单、两套状态。
- 应急采购单状态：待临时审批 → 采购接单 → 询价 → 定标 → 已发货 → 待验收 → 待临时入库 → 待补资料 → 已完成。
- 入库单状态：待入库 → 部分入库 → 全部入库 → 分配完成 → 转正。
- 状态值读法：个别表用英文（pending／processing／closed）＝"待处理／处理中／已关闭"；业务单据一律用中文。

## 四、暂估 / 红冲 / 正式入库
- 暂估：货到票未到，先入账（不影响领用）；
- 红冲：发票到后冲回暂估；
- 正式入库：凭票入账。
- 分工：**库房只碰货、不碰票**；票的事在采购与财务。

## 五、金额与口径
1. 录单金额 = **含税含运总价**（系统永不加税放大）；税率仅用于价内倒拆展示（默认 13%，无票填 0）；
2. 报价页录**含税单价**，运费单列；合同金额含运费，与报价的差额即运费，不算异常；
3. 三个字段别混：
   - 交易模式 = 业务口径（常规／应急）；
   - 结算方式 = 现结 / 月结（**"月结"是月底汇总的唯一准入字段**）；
   - 账期 = 仅用于显示的文本（如"月结30天"）。

## 六、三套金额门槛（一张表记全）
| 业务 | 门槛与期限 |
|---|---|
| 采购 | 1000 元分流（小额/常规） |
| 维修 | 2000 元签合同；定损超预估 ≥200 元且未询价 → 自动变更审批 |
| 应急采购 | 5000／20000 两档；每月上限 3 次；价格偏差 ≤20%；承诺补单 3 天；到货 2 天；分配 3 天 |
| 手工应急入库 | 限 2000 元 |

## 七、审批与责任
- **谁批：以「系统设置 → 审批流配置」中的实际审批人为准**，角色名只作参考（历史上存在角色名与实际审批人不一致的情况，正在收敛）；
- 维修类审批统一走 穆娇（全档）；
- 一票归一：同一环节只走一次审批，已办过的再点会被拦（防重复验收、重复入库、重复付款）。

## 八、遇到分歧怎么办
1. 先看本表定义；
2. 再看对应流程图（页头或各业务页右上角 📋／⚡／📦／🔧 四个按钮，节点可点击直达页面）；
3. 仍不一致，报系统管理员统一改本表——**不要各自沿用旧叫法**。

## 九、常见"看不懂"提醒
- 系统更新后，页面底部会自动弹「系统已更新，立即刷新」，点一下即可；异地电脑没刷新，是"看不到新功能/新流程图"最常见的原因。
- 品名为「3333 / 222」这类占位、或带【演示】标记的单据不是真实业务，看到不必处理，也不要照它学流程。
